A tracked prompt is one question, while a persona is a buyer with a job title, a company, a current tool stack and objections, who has a whole conversation with each engine that has web search. The **Persona visibility** card on the Personas page shows how often you come up in those conversations and how that changes over time, with each line averaged over the last seven days.

## Generate personas

Notra generates a starting set of five personas from your website and audience. **Add persona** generates one more from a short description, for example "an agency founder comparing AI visibility tools for clients, with a tight budget", and Notra fills in the profile and memories.

## What a persona contains

| Section | Contents |
| --- | --- |
| Employment | Job title and company profile |
| Behavior | Motivations and how they search |
| Goals and pain points | What they want and what blocks them |
| Current stack | Up to six tools they already use |
| Buying triggers and objections | Why they would buy, and why not |
| Memories | Background facts, preferences and constraints |

From the profile and memories Notra generates fixed **conversation prompts**. Every engine receives the same messages in the same order, so you can compare results across engines and scans. Editing a persona regenerates its prompts.

## Scans and cost

- Personas talk to every enabled engine that has web search during each scan, in the [language](/geo/languages) their messages are written in, as long as you track it. New and regenerated personas write in your prompt language; personas created before that count as English and only run when English is tracked, so regenerate them to switch. Engines labelled **No web search**, such as Grok and Cursor, don't get persona conversations. Each persona sends up to two messages per engine per scan, shown as **Max. messages**.
- Each persona answer counts as two AI answers against your quota.
- A project can have up to five active personas, so archive one before you add or reactivate another.
- **Pause scans** keeps a persona but skips it in scans, while **Archive** removes it from future scans and keeps its history.

## Personas in the API

<Visibility for="agents">

Generation runs in the background, and only one job runs per project at a time. With no body it creates the starting set of five; `brief` adds one persona; `personaId` regenerates one in place, and with `promptsOnly: true` only its conversation prompts.

```bash
curl -X POST https://api.usenotra.com/v1/projects/$PROJECT_ID/geo/personas/generate \
  -H "Authorization: Bearer $NOTRA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "brief": "an agency founder comparing AI visibility tools for clients, with a tight budget" }'

# Poll until job.status is "completed" or "failed"
curl https://api.usenotra.com/v1/projects/$PROJECT_ID/geo/personas/generation \
  -H "Authorization: Bearer $NOTRA_API_KEY"
```

Play one persona now and read its conversation turns:

```bash
curl -X POST https://api.usenotra.com/v1/projects/$PROJECT_ID/geo/personas/$PERSONA_ID/run \
  -H "Authorization: Bearer $NOTRA_API_KEY" \
  --max-time 330

curl "https://api.usenotra.com/v1/projects/$PROJECT_ID/geo/personas/$PERSONA_ID/results" \
  -H "Authorization: Bearer $NOTRA_API_KEY"
```

<Warning>
  A run behaves like a [conversation run](/geo/conversations#running-a-conversation-now): API engines answer during the request, consumer apps are queued as a scan named by `queuedScanId`, and after four minutes the API answers `409` while the run finishes on its own. Don't retry; read the results instead. Runs allow 10 requests and generation 5 requests per 10 minutes per organization.
</Warning>

`PATCH /geo/personas/{personaId}` accepts `enabled` and any of `name`, `role`, `company`, `summary`, `searchStyle` and `profile` lists; editing details clears the conversation prompts, so regenerate them with `personaId` and `promptsOnly: true` before the next run. `DELETE` archives the persona and `POST …/restore` brings it back paused. `GET /geo/personas/activity` returns daily checks and mentions per persona.
