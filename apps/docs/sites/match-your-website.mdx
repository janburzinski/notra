Three kinds of files make the blog match your website: your own header, your own footer and slots that fill fixed places on every page.

<Tip>
  When you create a site from a repository without `blog.json`, Notra offers **Open starter PR (optional)**, which reads your Brand Identity and website and opens a pull request with `blog.json`, `header.mdx`, `footer.mdx` and a first post that already use your logo, colors and links.
</Tip>

## Header and footer

Add `header.mdx` or `footer.mdx` next to `blog.json`, and each replaces the theme's own. Write plain markup with Tailwind classes. You can paste HTML from your landing page if you change `class` to `className`, close empty tags like `<img />` and remove `<!-- -->` comments, because these files are [MDX](/sites/components/overview#mdx-differs-from-markdown).

```mdx header.mdx
<header className="border-b border-border">
  <div className="site-container flex h-16 items-center gap-6">
    <a href="https://acme.com" className="flex items-center gap-2 font-semibold">
      <img src="/images/logo.svg" alt="" className="h-6" />
      Acme
    </a>
    <SiteAreas />
    <nav className="ml-auto hidden gap-6 text-sm md:flex">
      <a href="https://acme.com/product" className="text-muted-foreground hover:text-foreground">Product</a>
      <a href="https://acme.com/pricing" className="text-muted-foreground hover:text-foreground">Pricing</a>
    </nav>
    <ThemeToggle />
  </div>
</header>
```

These built-in components cover what the theme's header and footer did:

| Component | What it renders |
| --- | --- |
| `<SiteAreas />` | The Blog and Changelog switch, with the current one highlighted, and nothing when only one section is on |
| `<ThemeToggle />` | The light, dark and system switch (hidden when `appearance.strict` is set) |
| `<PrivacySettings />` | The link that reopens the [c15t](/sites/integrations/consent/c15t) privacy settings, for your own footer (renders nothing when c15t is off) |

Interactive parts like a mobile menu go in a component in `snippets/` that you import as usual. See [Your own components](/sites/custom-components). Wrap your content in `site-container` to give it the same width as the posts below (it follows `layout.width`). Theme colors are available as these Tailwind classes: `bg-background`, `text-foreground`, `bg-muted`, `text-muted-foreground`, `border-border`, `bg-card`, `bg-primary` and `text-primary`.

Write your site name and links into the header and footer directly. Both get the current page as `page` (`index`, `entry`, `author`, `tag` or `not-found`), `area` (`blog` or `changelog`) and `path`, also available as `props.page`, `props.area` and `props.path`, so you can show something on some pages only:

```mdx footer.mdx
{props.area === "changelog" && <p className="site-container text-sm text-muted-foreground">Subscribe to the changelog with RSS.</p>}
```

If your blog runs under a path of your website and your main site already saves the light or dark choice, set [`appearance.storageKey`](/sites/customize/design#light-and-dark-mode) to the same key so `<ThemeToggle />` and your main site share it.

With your own header, the navbar IDs like `#topbar-cta-button` don't exist, so use your own class names. Under your footer, Notra adds a row with a "Report abuse" link and, when Notra branding is on, the "Powered by Notra" badge. Style it with `#notra-attribution` so it matches your footer:

```css style.css
#notra-attribution { background: var(--card); border-color: transparent; }
```

## Slots

Slots add your own content at fixed places, and each one is a file in `slots/`. Every slot gets `site` and `area`, and some get more:

| File | Where it appears | More data you can use |
| --- | --- | --- |
| `slots/blog-hero.mdx` | Replaces the top of the blog home | |
| `slots/changelog-hero.mdx` | Replaces the top of the changelog | |
| `slots/before-post.mdx` | Above every post | `post` |
| `slots/after-post.mdx` | Below every post | `post` |
| `slots/sidebar.mdx` | Next to every post under "On this page" on wide screens, above the post on phones and below the post in the narrow layout | `post` |
| `slots/after-changelog-entry.mdx` | Below every changelog entry, on the index and on the entry's page | `entry` |
| `slots/before-footer.mdx` | On every page, below the content and above the footer | `page`, `path`, `section` |

| Data | Fields |
| --- | --- |
| `site` | `name`, `description` |
| `area` | `id` (`blog` or `changelog`), `title`, `description`, `url`, `path` |
| `post` | `title`, `description`, `date` (formatted), `tags`, `authors` (each with `name`, `title`, `url`), `url`, `path` |
| `entry` | `title`, `version`, `date` (formatted), `url`, `path` |
| `page` | `index`, `entry`, `author`, `tag` or `not-found` |
| `path` | The page's path, like `/blog/2026/launch` |

`url` is the full address on your site's domain, like `https://acme.com/blog`. `path` is the same address without the domain, like `/blog`, as the theme's own links use it, so links stay on previews and on the domain the page is served from. Use `path` for links on the page and `url` where you need a full address, like a share link.

To link back to the blog or changelog home, use `area.path`. Don't write a relative link like `../`: pages have no trailing slash (`/blog/launch`, and `/blog/launch/` redirects there), so `../` from a post goes to the root of the domain, not to `/blog`.

The hero slots span the full content width, so wrap their content in `<div className="mx-auto max-w-(--layout-index)">` to line it up with the posts below.

```mdx slots/after-post.mdx
<div className="mt-12 rounded-xl border border-border p-6">
  <p className="font-semibold">Enjoyed "{post.title}"?</p>
  <p className="mt-1 text-sm text-muted-foreground">Try Acme free for 14 days.</p>
  <a href="https://acme.com/signup" className="mt-4 inline-block rounded-lg bg-primary px-4 py-2 text-sm text-white">Start free trial</a>
</div>
<a href={area.path} className="mt-6 inline-block text-sm text-muted-foreground hover:text-foreground">← More from {area.title}</a>
```

`before-footer` gets `area` as `blog` or `changelog` rather than the object above, and the object as `section` instead, so `section.path` links to the current home. To show it on posts only, check the page:

```mdx slots/before-footer.mdx
{props.page === "entry" && props.area === "blog" && (
  <div className="site-container rounded-xl border border-border p-6">Get new posts by email.</div>
)}
```

A call to action under every post, a newsletter form or a product card in the sidebar each fit in a slot. A file in `slots/` with any other name stops the build with `Unknown slot` and the list of valid names. Inline SVG in a slot, header or footer takes its attributes the HTML way, like `stroke-width`, because the React form `strokeWidth` is dropped.

## Your own CSS

For anything the settings and files don't cover, add `style.css`, which loads after the theme so it can override any style. See [Design and CSS](/sites/customize/design#your-own-css).

## What isn't allowed

Header, footer and slots follow the same rules as posts, so imports only come from your repository and Notra doesn't allow `<script>` tags. Put JavaScript in `script.js` instead. See [Custom scripts](/sites/custom-scripts).
