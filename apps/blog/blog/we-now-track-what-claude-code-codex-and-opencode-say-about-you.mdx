A developer in a terminal asking Claude Code to "add a rate limiter" is making a buying decision. Whatever package the agent reaches for gets installed and shipped. No search results, no comparison page, no chance for you to make a case. We started tracking those recommendations too.

## A new kind of answer engine

GEO has mostly meant watching what ChatGPT, Claude, Gemini, and Perplexity say when someone asks a question. A lot of developers never open a chat window for that. They stay in Claude Code, Codex, or OpenCode and let the agent just handle it. If your product never comes up in those sessions, you lose a sale you never knew was happening.

## What we added

Coding agents now show up in your GEO scans the same way chat engines do. We run real sessions against Claude Code, Codex, OpenCode, and Cursor, and check whether your product comes up, where it ranks, and what gets recommended instead. Vercel's fx.sh is in there too, as an early, experimental engine. It all sits in the same dashboard as your other engines, so you can compare a Claude Code answer to a ChatGPT answer in one place.

## Why this matters

Chat engines tell you what people read about you. Coding agents tell you what people actually install. That is a sharper signal: it shows whether your docs and your package name are clear enough for an agent to pick you over the three other libraries that do the same thing. If a coding agent keeps reaching for a competitor, you can see it and fix it, instead of finding out a quarter later when your adoption numbers look off.

Open your GEO dashboard and check the engine breakdown. Claude Code, Codex, and OpenCode are in there now, next to ChatGPT and Gemini.
