# Dashboard client benchmarks

Two scripts measure what the dashboard ships to the browser. Both run against a
local production build with the synthetic fixture from
`scripts/performance/setup-dashboard.sh` (see `scripts/performance/README.md`
for the build and start commands). They refuse non-loopback URLs and never need
production credentials.

## Page load

```sh
node scripts/benchmarks/dashboard-pages.mjs http://127.0.0.1:3000 .hoplite/artifacts/benchmarks/pages.json 5
```

Loads each page in a fresh context with the cache disabled, at 1440x900 and 4x
CPU throttling (`CPU_SLOWDOWN` overrides it). It reports the median of the runs
for LCP, TBT (long tasks after FCP, minus 50 ms each), Chrome's
`ScriptDuration`, and the number and transferred (compressed) bytes of the
scripts the page fetched. `PAGES` takes a comma-separated list of paths below
the organization slug; the default is home, GEO, content, chat, brand identity
and automation. The script URLs of the first run are written next to the output
as `<output>-<page>.urls.json`.

## Bundle composition

```sh
node scripts/benchmarks/dashboard-bundle.mjs apps/dashboard/.output/public/assets [urls.json]
```

Decodes the client source maps and attributes generated bytes to npm packages
and workspace folders. Pass a `urls.json` from the page benchmark to count only
the chunks one page loaded; without it every chunk is counted. Source maps are
off in normal builds, so add `sourcemap: true` to
`environments.client.build` in `apps/dashboard/vite.config.ts` for the
measurement build only and do not commit it.
